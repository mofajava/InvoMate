## 1. 背景

InvoMate 用來取代目前用記事本手動記錄的進貨與庫存。手記涵蓋民國 114 年紫山藥、糖、三花麵粉、地瓜粉的進貨，以及期末剩餘扣抵。本階段只處理**進貨登打**與**庫存餘額**，不做出貨、成品成本、應收應付。

已對齊的產品決策：

- 手記中的交易**全部是進貨**。陳美美、溪湖、山上、王小姐、西螺都是供應商；單價差來自品級與來源，不是買賣方向。
- 品項採**主檔 + 可隨時新增**（預先有山藥／糖／麵粉／地瓜粉，之後可加成品而不改程式）。
- 第一版**不做出貨登打**。
- 以**響應式網頁**支援手機、平板、桌機瀏覽器；不做原生 App。
- **網站放 GitHub Pages**（靜態網頁，任何裝置用瀏覽器打開同一個網址）。
- **帳本綁個人 Google 帳號，存在 Google 雲端硬碟的 JSON 檔**（不是 Google 文件、也不是試算表當主檔）。打開 App → 登入 → 從雲端讀入初始化；記帳後自動寫回雲端；換手機／平板只要登入同一 Google 帳號即可。

## 2. 目標與非目標

### 2.1 目標

1. 用表單登打進貨：日期、供應商、品項、品級、數量、單位、單價、金額、備註。
2. 金額預設為「數量 × 單價」，可覆寫；覆寫時標示與公式的差額。
3. 同一供應商 + 品項帶出上次單價（對應陳美美「一斤 43 元」沿用多筆）。
4. 依品項（必要時加品級）顯示目前庫存。
5. 進貨增加庫存；盤點／耗用／期末剩餘用「庫存調整」，不得記成進貨。
6. 進貨可多條件查詢（供應商、日期區間、金額、數量、品項等可同時套用），並對查詢結果小計。
7. 畫面用民國年，儲存 ISO 日期；拒絕無效日期。
8. 單人；用**自己的 Google 帳號登入**（資料在該帳號的雲端硬碟，不在 GitHub repo）。
9. 任何能上網的手機／平板／桌機瀏覽器，打開 GitHub Pages 網址即可記帳（不必同一 Wi‑Fi、不必開著家裡電腦）。
10. 開啟時從雲端載入；變更後自動儲存回雲端。
11. 已登入 Google 時可**匯出 xlsx 與 pdf** 到同一個雲端硬碟資料夾（亦可下載到裝置）。匯出是快照，不是正式帳。

### 2.2 非目標（明確排除）

- 出貨登打、客戶主檔、銷貨收入。
- 應收／應付、損益表、誰欠誰。
- 加工配方、原料耗用轉成品、成品每斤成本（例如 37.91）。
- 多人同時編輯、帳號權限、邀請他人寫同一本帳（同時開兩台裝置採「後寫蓋前寫」，見 US-13）。
- 伺服器資料庫（Turso／Supabase／本機 SQLite 當主檔）。GitHub Pages **沒有後端**，不能跑 SQLite 服務。
- 以 **Google 文件或試算表儲存格當正式帳**（難驗證、易改壞）。硬碟上放 **一份 JSON** 才是主檔；xlsx／pdf 僅作匯出快照（可在 Drive 用試算表打開 xlsx，但不要改完當主檔）。
- 不接 Google Sheets API 去「活同步」一份試算表；匯出是產出檔案再上傳。
- 把帳本 JSON 提交進 GitHub（repo 只放程式；資料在使用者自己的 Drive）。
- 手記 `data.txt` 的一次性自動匯入（可列為後續加分，不阻塞 Phase 1 驗收）。
- 同一張進貨單拆成多品項「單據」概念（同一天混開記成多筆進貨即可）。
- 原生 iOS／Android App、PWA 安裝、離線優先、推播。手機／平板只要求**瀏覽器開網頁**可用。

## 3. 使用者與使用情境

唯一角色：**記帳者**，用瀏覽器打開 GitHub Pages 上的 InvoMate，以自己的 Google 帳號登入。倉儲用手機、辦公室用平板／桌機都可以；換裝置只要同一 Google 帳號。須能連網以讀寫雲端。

### US-1 登打一筆進貨

**我是**記帳者，**想要**輸入日期、供應商、品項、數量、單價，**以便**系統自動算出金額並列入該品項庫存。

驗收：

- 必填：日期、供應商、品項、數量、單位、單價。
- 儲存後列表可見該筆；該品項庫存增加對應基準數量。
- 金額欄預填 `數量 × 單價`（整數元，見計算規則）。

### US-2 沿用上次單價

**我是**記帳者，**想要**選好供應商與品項後自動帶出上次單價，**以便**像手記「其後皆 43 元」一樣少打字。

驗收：

- 帶出該供應商 + 該品項（含品級，若有）最近一筆進貨的單價。
- 使用者可改單價；改了只影響本筆，不回寫歷史。
- 若無歷史，單價留空，不可用 0 當預設。

### US-3 覆寫手記金額

**我是**記帳者，**想要**金額與「數量 × 單價」不同時仍能存檔，**以便**把舊手記原樣登入、不改歷史數字。

驗收：

- 可改金額；若與公式不同，該列顯示差額（例如「公式 58,860，手記 58,800，差 −60」）。
- 小計用**實際儲存金額**加總，不是公式金額。
- 庫存數量仍用數量，不受金額覆寫影響。

### US-4 箱與斤並存

**我是**記帳者，**想要**用箱進貨但庫存用斤，**以便**對齊王小姐／西螺「100 箱 = 3,333 斤」。

驗收：

- 紫山藥可選單位「斤」或「箱」。
- 選箱時，系統用品項換算顯示基準斤數；庫存加減用基準斤數。
- 換算見設計文件；100 箱必須得到 3,333 斤（允許以分數 `100/3333` 或等價 20 kg／台斤規則實作，但驗收以手記整數為準）。

### US-5 同一天混開多品項

**我是**記帳者，**想要**把「三花 90 包 + 地瓜粉 9 包」記成兩筆同一天的進貨，**以便**各品項庫存分開算。

驗收：

- 不強制「一張單」；兩筆獨立進貨、同一日期即可。
- 供應商可為空白以外的值；手記未寫供應商時可用「未指定」或當日備註，但供應商主檔必須能新增（例如「益」）。

### US-6 品級「醜」

**我是**記帳者，**想要**在進貨列標記品級（例如醜），**以便**正貨與醜貨庫存可分開看。

驗收：

- 品級非必填；未填視為正貨／未分級。
- 庫存報表可依「品項 + 品級」列示。
- 「醜」不是供應商，也不是獨立品項主檔（除非使用者自己新增）。

### US-7 新增供應商與品項

**我是**記帳者，**想要**不改程式就新增供應商或品項，**以便**之後登錄「山藥成品」等新東西。

驗收：

- 供應商、品項皆有主檔維護（新增／重新命名；停用即可，Phase 1 可不做真刪除）。
- 預先種入：供應商 陳美美、溪湖、山上、王小姐、西螺；品項 紫山藥、糖、三花麵粉、地瓜粉。
- 新增品項時指定基準單位（斤或包），可選輔助單位換算。

### US-8 看庫存與小計

**我是**記帳者，**想要**依查詢結果看到數量與金額小計，**以便**核對手記「總共 686,643 元／15,909 斤」。

驗收：

- 進貨列表的小計與筆數，一律依**目前查詢條件**計算（`sum(qtyInBase)`、`sum(amount)`、筆數）。
- 庫存頁顯示各「品項 + 品級」目前餘額（進貨基準量 + 調整量）。庫存本身不受進貨列表篩選影響（庫存是現況，不是查詢切片）。

### US-8b 多面向查詢進貨

**我是**記帳者，**想要**用多個條件查出進貨，**以便**例如「陳美美 9 月」「金額大於 10 萬」「一次進超過 1,000 斤」不必用眼睛掃整本帳。

條件可**同時**成立（AND）。沒填的條件不限制。要能一鍵清除。

| 面向 | 操作 | 說明 |
|---|---|---|
| 供應商 | 選一個或多個 | 含已停用但仍有歷史的名稱 |
| 品項 | 選一個或多個 | |
| 品級 | 未分級／醜／其他（含自由輸入比對） | 空＝不限 |
| 日期 | 起～迄（民國，可只填一邊） | 含起含迄；取代「只選年／月」為主軸，年／月可當快捷（選 114 年 9 月＝填該月起迄） |
| 金額 | 最小～最大（實際入帳金額） | 元、整數；只填最小＝以上 |
| 數量 | 最小～最大 | 比對**基準數量** `qtyInBase`（箱已換算成斤），避免 100 箱與 100 斤混比 |
| 單價 | 最小～最大 | 依該筆計價單位的單價（不跨單位換算；篩選時畫面提示「依該筆單價」） |
| 備註 | 關鍵字 | 包含即可，不分大小寫 |
| 僅覆寫金額 | 開關 | 只看手記金額與公式不同的列 |

另外：

- 排序：日期、金額、基準數量、供應商；升／降。預設日期新到舊。
- 無符合時顯示空狀態，小計為 0，不是錯誤。
- 查詢在瀏覽器內對已載入帳本過濾（資料量為手記級），不必雲端搜尋 API。
- 手機：條件收合；已套用的條件用可刪除的標籤顯示（例如「陳美美」「金額≥100,000」），不必打開面板也看得到。
- 驗收例：供應商陳美美 → 15,909 斤、686,643 元；日期 114/9/1～114/9/29 且陳美美 → 不含 8/30 那筆；金額 ≥ 180,000 → 含王小姐 100 箱與之後大單、西螺 40 萬。

### US-9 庫存調整（期末剩餘）

**我是**記帳者，**想要**登記「剩 10 包麵粉、10 包糖」這類盤點結果，**以便**庫存不是永遠只增不減。

驗收：

- 調整必填：日期、品項、基準數量（可正可負）、原因。
- 原因至少含：盤點、耗用、報損、其他。
- 「剩 10 包」語意：若要以餘額為 10，應能輸入盤點後餘額或輸入差額；Phase 1 採用**差額調整**（例如目前 20 包、要剩 10 包，則調整 −10）。畫面須寫清楚是「增減量」不是「盤後餘額」。
- 調整不產生進貨金額；不列入進貨小計。手記「−17,650 元」是成本扣抵，**Phase 1 不記金額**，只調數量。金額影響留給 Phase 2。

### US-10 拒絕無效日期

**我是**記帳者，**想要**系統拒絕 12/38 這類日期，**以便**不把壞資料寫進帳。

驗收：

- 儲存前驗證日曆日期（含閏年）。
- 畫面輸入民國年；例如民國 114 年 12 月 4 日 → 儲存 `2025-12-04`。
- 錯誤訊息需指出日期無效，不得靜默改成最接近的合法日。

### US-11 手機與平板瀏覽

**我是**記帳者，**想要**用手機或平板瀏覽器打開 GitHub Pages 網址就能記帳，**以便**換機、出外都不必開家裡的電腦。

前提：能連網，並以同一 Google 帳號登入。資料不存在手機裡。

驗收（斷點見設計；以下寬度為 CSS 邏輯像素）：

- **手機**（寬度小於 768）：主導覽不擠成一排小字；改為選單或底欄，點得到、不擋內容。
- **平板**（768–1023）與**桌機**（≥ 1024）：導覽可見；列表可讀。
- 進貨／調整表單：欄位垂直堆疊或最多兩欄；觸控目標約 44px；輸入框使用合適的 `inputmode`／鍵盤（數量、單價用數字）。
- 進貨列表在手機改為**卡片**（日期、供應商、品項、數量、金額一卡）；小計固定在列表上方或下方且捲動時仍看得到或重複顯示一次。平板可用表，欄位過多時橫向捲動表格，表頭凍結或卡片化，**不得**讓整頁只能橫滑才能操作導覽。
- 篩選在手機可收合，預設不佔滿第一屏。已套用的查詢以標籤顯示。
- 頁面設 viewport meta；直向為主，橫向不破版、不出現無法關閉的橫向溢出（允許表格區塊內捲動）。
- 不要求原生 App、手勢捷徑。沒網路時無法初始化或儲存，須顯示清楚錯誤（可選：顯示上次快取為唯讀，Phase 1 可不做唯讀快取）。

### US-12 開啟讀雲端、記帳後自動存雲端

**我是**記帳者，**想要**打開網頁就載入我的帳、打完就存回 Google 雲端硬碟，**以便**換手機後登入同一帳號仍是最新資料。

驗收：

- 未登入：只顯示登入（Google），不顯示空帳當正式資料。
- 登入後：在 Drive 尋找 App 專用檔（見設計，檔名如 `invomate-ledger.json`）。沒有則建立並種入預設供應商／品項。
- 載入完成前有載入狀態；失敗（拒權、沒網路）顯示可重試訊息。
- 新增／改／刪進貨、主檔、調整後，於短延遲內自動寫回 Drive（例如停止操作 0.5–2 秒後）。畫面顯示「儲存中／已儲存／儲存失敗」。
- 關頁再開、或換裝置登入同一 Google 帳號：看到剛才的資料。
- 使用者可在 Google 雲端硬碟看到該檔（放在 `InvoMate` 資料夾），但**不要用文件或試算表手動改 JSON** 當日常作業。
- GitHub 上只有程式，沒有帳本內容。

### US-13 單人、後寫蓋前寫

**我是**記帳者，**想要**知道兩台裝置同時開著會怎樣，**以免**以為會自動合併。

驗收：

- Phase 1 不做合併衝突 UI。後成功寫入的那份整檔覆蓋雲端。
- 畫面顯示本機最後成功儲存時間。說明「請勿兩台同時記帳」。

### US-14 授權後匯出 xlsx／pdf 到雲端硬碟

**我是**記帳者，**想要**用已經綁定的 Google 帳號，把目前帳本匯成 Excel 或 PDF 存進雲端硬碟，**以便**用試算表核對、列印或傳給別人，而不把 JSON 當給人看的格式。

驗收：

- 須已 Google 登入（沿用讀寫帳本的授權，scope 仍以 `drive.file` 為準，不另要全硬碟）。
- 可產出 **xlsx**（至少三個工作表：進貨、庫存、調整；進貨含日期、供應商、品項、品級、數量、單位、基準數量、單價、金額、是否覆寫、備註；有小計列）。
- 可產出 **pdf**（中文可讀：進貨列表＋金額／數量小計，以及庫存餘額；紙張直向 A4）。
- 匯出後檔案出現在 Drive 的 `InvoMate/exports/`，檔名含時間（例如 `進貨帳_114-12-04_1530.xlsx`）。成功後畫面給 Drive 開啟連結或「已存到雲端硬碟」。
- 同步提供「下載到此裝置」，沒有 Drive 寫入權限時至少本機下載仍可用（若權限被撤就提示重新登入）。
- 可選擇「目前篩選」或「全部進貨」；庫存／調整隨全部帳本。
- 匯出**不回寫** JSON 主檔；改 xlsx 不會更新 App。
- 手機上按鈕可點、匯出中有進度；大檔在手記量級應在數秒內完成。

## 4. 計算與領域規則

### 4.1 日期

- 顯示：民國年 `YYY/M/D` 或 `YYY年M月D日`。
- 儲存：ISO `YYYY-MM-DD`（民國 YYY = 西元 − 1911）。
- 手記跨年：114 年 8 月～115 年 3 月；1/19、2/2、3/2 等無年份的列，依手記脈絡屬 114 年進貨年度的次年（西元 2026）。系統不自動猜年，**年份由使用者選**；預設為今天的民國年。

### 4.2 金額

- 幣別：新台幣，整數元（不存小數）。
- 公式金額 = round_to_integer(數量 × 單價)。數量可為小數（斤到整數即可；箱換算後的斤可為小數，顯示最多 2 位，金額仍對「計價用數量」計算）。
- **計價用數量**：使用者輸入的數量（斤或箱或包），不是換算後的基準數量，除非使用者是用基準單位輸入。
- 例：50 箱、每箱 1,800 元 → 金額 90,000；同時 50 箱 → 1,666.5 斤庫存（手記寫 1,666 斤，見換算規則）。
- 例：1,308 斤 × 45 元 → 公式 58,860；手記 58,800 → 覆寫金額 58,800，差額 −60。

### 4.3 單位與換算

| 品項（預設） | 基準單位 | 輔助單位 | 換算（驗收基準） |
|---|---|---|---|
| 紫山藥 | 斤（台斤） | 箱 | 100 箱 = 3,333 斤（1 箱 = 33.33 斤 = 20 kg） |
| 糖 | 包 | — | 1 包 = 1 包 |
| 三花麵粉 | 包 | — | 1 包 = 1 包 |
| 地瓜粉 | 包 | — | 1 包 = 1 包 |

庫存只累加**基準單位數量** `qtyInBase`。

手記王小姐 50 箱寫 1,666 斤：3,333 / 100 × 50 = 1,666.5。系統庫存用 1,666.5，列表可同時顯示使用者輸入的 50 箱。不得為了遷就手記整數而把換算改成 33.32。

### 4.4 庫存餘額

```
balance(item, grade) = sum(inbound.qtyInBase) + sum(adjustment.qtyInBase)
```

- `adjustment.qtyInBase` 減少庫存時為負。
- Phase 1 不允許庫存餘額為負？**允許**（先記再說），但庫存頁對負數用醒目樣式。理由：舊帳可能先調後補登。

### 4.5 小計

- 進貨小計：篩選範圍內 `sum(amount)` 與 `sum(qtyInBase)`。
- 不把庫存調整金額算進去（Phase 1 調整無金額）。
- 「手記封面總額」與系統重算不同時，系統**以重算為準**，並可在說明／核對區顯示手記數字（若有手動填的核對備註）。Phase 1 不需「手記封面金額」欄位；核對靠驗收案例。

## 7. 開放問題（不阻塞 Phase 1）

- **Q1** 王小姐 50 箱那列沒有日期。實作預設：日期必填，由使用者自訂；文件建議填 114/10/17 與 114/11/6 之間並在備註寫「手記無日期」。
